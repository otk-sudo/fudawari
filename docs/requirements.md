## 0. この文書の読み方

- 本文は、特記がない限り**事実**（会話またはモックで確認できた最終的な合意）。
- **【提案】**：この文書を書いた計画担当の推測・提案。合意していないため、採用する前にユーザーへ確認する。
- **【未決 Uxx】**：書いた時点で決まっていなかった事項。番号は「13. 未決事項と決定」と対応する。**U1〜U24 は 2026-10-16 にすべて決定した（13.1）。本文の【未決 Uxx】は 13.1 の決定内容で読む。**
- 会話の中で方針は何度も変わった。後の発言を優先し、取り下げた案は「12. 採用しなかった案」にまとめた。

- モック各画面の右上にある「見え方の確認」（一般／協力者／管理者、イベント開催中／終了後などの切り替え）はモックで見え方を確かめるためのもので、**本番の機能ではない**。
- モックの数値（2026夏イベの札・倍率・艦）はダミーまたは説明用。実装では定義データから組み立てる。

## 1. 目的と位置付け

- 艦これのイベントで、**特効を踏まえて「どの艦をどの札に回すか」を計画する** Web アプリ。
- 背景：制空権シミュレータでも札の割り振りはできるが、「この艦はどの札で特効が効くか」を踏まえて割り振るのが面倒。そこを支援する。
- 役割分担：**特効を踏まえて札を決めるのがこのツール、編成を組むのが制空権シミュ**。
- 想定規模：手持ちの艦が 600 隻以上になることもある。同名艦（サブ艦）も別の個体として扱う。
- 名前：リポジトリ名・フォルダ名は `fudawari`。画面上のアプリ名はモックでは「札割り振りプランナー」。「札割りプランナー」へ変えるかは【未決 U4】。
- 日本人向けアプリ。画面の文言はすべて日本語。

## 2. 利用者と権限

### 2.1 権限の種類

| 権限 | 説明 | ログイン |
|---|---|---|
| 一般利用者 | 艦娘を取り込み、札割りを計画する人。 | 不要 |
| 協力者 | 管理者から招待され、イベント定義（札・段階・特効）を編集する人。一般の画面もすべて使える。 | 必要 |
| 管理者 | アプリの持ち主。協力者の権限に加え、イベントの新規作成と協力者の管理ができる。 | 必要 |

- 協力者の権限には期限がない（管理者が外すまで続く）。
- 管理者は自分自身を外せない。
- 【提案】管理者は 1 人（ユーザー本人）を想定している。最初の管理者は DB に直接登録する。

### 2.2 左メニューの出し分け（全画面共通）

| 権限 | 表示する項目 |
|---|---|
| 一般利用者 | 一覧／割振／取込／差分／設定 |
| 協力者 | 上記に加えて、「管理」の区切りの下に「定義」 |
| 管理者 | 上記に加えて、「管理」の区切りの下に「定義」「協力者」 |

- 左上の「札」ロゴを押すとホームへ移動する。
- 「設定」は画面を移動せず、ウィンドウで開く（3.6）。
- 管理者・協力者は、一般の画面にいるときもログイン中の権限に応じた管理メニューを常に表示する（一般の画面に移ると管理メニューが消える作りは不可）。
- 「履歴」メニューは置かない。

### 2.3 画面と操作の可否

| 画面・操作 | 一般 | 協力者 | 管理者 |
|---|:-:|:-:|:-:|
| ホーム・一覧・割り振り・取り込み・差分・設定 | ○ | ○ | ○ |
| 設定の「アカウント」欄（ログイン中の名前・権限・ログアウト） | × | ○ | ○ |
| イベント定義画面を開く | × | ○ | ○ |
| 最新イベントの札・段階・大事さ・特効を編集し、下書きを保存する（終了前のみ） | × | ○ | ○ |
| 最新イベントの変更を公開する（「変更を公開する」） | × | ○ | ○ |
| 最新イベントの終了日時を変える | × | ○ | ○ |
| 最新イベントのイベント名・開始日時を変える | × | × | ○ |
| イベントの新規作成（元にするイベントとして過去のイベントを選べる） | × | × | ○ |
| 保存の記録を見る | × | ○ | ○ |
| 終了したイベントの定義を見る（閲覧のみ） | × | ○ | ○ |
| 協力者画面（招待リンクの発行・取り消し、協力者を外す） | × | × | ○ |

- 協力者にも「変更を公開する」ボタンが表示される（モックで確認。会話で制限する発言はない）。
- 協力者や一般利用者が協力者画面を開くと「このページは管理者のみ使えます」と表示する（モックで確認）。
- 【提案】一般利用者が定義画面の URL を直接開いた場合も、同じように拒否の表示を出す。

### 2.4 権限の強制

- 権限は DB の RLS（行レベルセキュリティ）で強制する。画面で隠すだけにしない。

## 3. 画面ごとの仕様

### 3.0 全画面共通

- 構成：左に幅 64px の縦メニュー（2.2）、上にヘッダー（画面名、最新イベント名、補足情報、主なボタン）、その下に本文。
- **札割りできるのは最新のイベントだけ**。一覧・割り振り・差分にイベントを選ぶ欄は置かず、最新イベント名（例「2026夏イベ」）を表示するだけ。前段・後段は分けない。
- ウィンドウ（設定、画像で保存、保存の記録）は画面の最前面に重ねて開き、開いている間は後ろの画面を触れない。× ボタン、「閉じる」（または「やめる」）、背景の暗い部分のクリックで閉じる。
- 倍率、海域、段階の並びは画面に固定で書かず、イベント定義から組み立てる。別のイベントの定義を読み込めば、表示もそのイベントの構成に変わる。

### 3.1 ホーム（モック：`Home.dc.html`）

- 左上の「札」から開く。
- ヘッダー：アプリ名、「開催中：〇〇イベ ／ 最終取り込み 10/15 20:40」。開催中のイベントがないときは「開催中：〇〇」を出さない。
- 「札割り」の区分：タイル 5 つ。各タイルにアイコン、名前、説明を表示する。
  - 一覧：決めた札割りを札ごとに見る
  - 割り振り：特効を見ながら艦を札に割り振る
  - 取り込み：制空権シミュレータの形式で艦娘を取り込む
  - 差分：イベント中に付いた札と計画を比べる
  - 設定：画面モードや文字の大きさなど（押すと設定ウィンドウを開く）
- 「管理」の区分（協力者・管理者のみ。見出しに権限名のバッジを付ける）
  - イベント定義：管理者には「札・段階・特効の設定、新規イベントの作成」。協力者には、開催中のイベントがあれば「開催中イベントの札・段階・特効を更新」、なければ「開催中のイベントがないため、いまは更新できるものはありません」と表示する。
  - 協力者（管理者のみ）：定義を編集できる人の招待・管理

### 3.2 一覧（札割り一覧、見るだけ。モック：`Main.dc.html`）

決めた札割りを眺めるための画面。この画面では割り振りの操作をしない。

- ヘッダー：「札割り一覧」、最新イベント名、「最終更新 10/15 21:40」、「画像で保存」（3.9 のウィンドウを開く）、「割り振りを編集」（割り振り画面へ移動）。
  - 【提案】「最終更新」は札割り（割り当て）を最後に変えた日時とする。
- 攻略の流れ：海域ごとに 1 行。段階を左から順に並べ、使う札の色で塗る。各段階に、段階名、札名、「特効 n 隻」（その札に割り当てた艦のうち、その段階で特効がある隻数）を表示する。大事さが「難所」の段階には「難所」の印を付ける。
- 表示の切り替え：「艦種ごとに並べる」（初期状態で ON）と「特効艦だけ」のトグルボタン。
  - 【未決 U24】モックはボタンだけで、動きは作られていない。【提案】「艦種ごとに並べる」が OFF のときは艦種の区切りをなくして Lv 順に並べる。「特効艦だけ」は、その札で特効がない艦を隠す。
- 札ごとの行：定義の札の並び順で、全札を 1 段ずつ表示する。
  - 左端の色帯：札名、その札を使う段階（例「E2-2・E2-3」）、「n 隻 ・ 特効 m 隻」。
  - 艦は艦種ごとにまとめ、艦種名の見出しを付ける。各艦に艦名、「Lv 運」、その札での最大倍率のバッジ（例「×1.24」。特効がなければ「–」）を表示する。その札で特効のない艦は少し薄く表示する。
  - 艦がいない札には「まだ割り当てがありません」と表示する。
- サブ艦の表記（「サブ」「（サブ）」）は出さない。同名艦は Lv と運で見分ける。

### 3.3 割り振り（専用画面。モック：`Assign.dc.html`、部品：`ShipCard.dc.html`）

艦を札に割り振るための画面。特効を確かめながら割り振りやすくする。

#### ヘッダー
- 「割り振り」、最新イベント名、操作の説明「ドラッグで別の札へ移動、カードに重ねると入れ替え」、「特効データ：2026/08/04 版」（使っている公開版の日付）。
- 「元に戻す」ボタン（モックはボタンだけ。何手まで戻せるかは【未決 U22】）。
- 「一覧で確認」：一覧画面へ移動する。

#### 控え（割り当てていない艦）
- 見出し：「控え」、「表示数 / 控えの総数 隻」（例「10 / 75隻」）、表示の詰め具合の切り替え「一行」「カード」。
- 検索欄：虫眼鏡付きの「図鑑ID 名称検索」。
- 「絞り込み」ボタン：押すと詳細条件が開く。入っている条件の数をボタンにバッジで表示する。条件の数＝外した改造状態の数＋「特効のある艦だけ」（ON なら 1）＋選んだ札の数。
  - 改造状態：未改造／中間改造／最終改造（チェックボックス。初期はすべて ON）。
  - 特効：「特効のある艦だけ」（初期は ON の状態で開く）。
  - 特効が効く札：定義の札ごとのチェックボックス（選んだ札のどれかで特効がある艦に絞る）。
- 「リセット」：艦種タブを ALL、並び順を艦型、改造状態をすべて ON、「特効のある艦だけ」を OFF、札の選択なしに戻す（モックの動作。初期状態と「特効のある艦だけ」の扱いが異なる点に注意）。
- 艦種タブ（制空権シミュの艦娘選択と同じ分け方。1 つだけ選ぶ）

  | タブ | 含む艦種 |
  |---|---|
  | ALL | すべて |
  | 空母 | 正規空母、装甲空母 |
  | 軽母 | 軽空母 |
  | 戦艦 | 戦艦 |
  | 航戦 | 航空戦艦 |
  | 重巡 | 重巡洋艦 |
  | 航巡 | 航空巡洋艦 |
  | 軽巡 | 軽巡洋艦、重雷装巡洋艦、練習巡洋艦 |
  | 駆逐 | 駆逐艦 |
  | 海防 | 海防艦 |
  | 潜水 | 潜水艦、潜水空母 |
  | 水母 | 水上機母艦 |
  | その他 | 潜水母艦、揚陸艦、補給艦、工作艦 |

- 並び順（プルダウン。初期値は**艦型**）。並び順ごとに見出しで区切る。

  | 並び順 | 見出しと並び |
  |---|---|
  | 艦型 | 艦型ごと（例「白露型」）。艦種の順（戦艦→航戦→正空→装空→軽空→重巡→航巡→軽巡→雷巡→練巡→駆逐→海防→潜水→潜空→水母→潜母→揚陸→補給→工作）、同じ艦種の中は艦型名の順、艦型の中は Lv の高い順 |
  | Lv | 「Lv 150 以上」「Lv 140 以上」のように 10 刻み。Lv の高い順 |
  | 特効の強さ | 一番効く札ごと（例「連合艦隊で効く」）、その中はスコアの高い順。最後に「特効なし」 |
  | 名前 | 「名前順」の 1 区切り。日本語の名前順 |

- 見出しを押すとその区切りを折りたためる（見出しには隻数を出し、スクロール中も上に固定する）。
- 控えの一覧部分だけをスクロールさせる。600 隻以上でも扱えるようにする（技術構成では仮想スクロールを使う）。
- 条件に合う艦がいないときは「条件に合う艦はいません」と表示する。
- 「特効を表示中：n 隻」の帯と「すべて閉じる」ボタン：特効を開いている艦があるときだけ、艦の一覧の上に表示する。押すとすべて閉じ、選択も外す。

#### 艦カード
- 一行表示（控えの「一行」）：艦名、「Lv 運」、特効の有無の印（「特効」または「－」）。
- カード表示（控えの「カード」と札の列）：艦名、特効の有無の印（「特効あり」または「特効なし」）、2 行目に「艦種 ・ Lv ・ 運」。
- カードの左端の色：札に置いた艦はその札の色。控えの艦は一番効く札の色（特効がなければ灰色）。
- 選ぶ前は、特効の有無だけを表示する。艦を選ぶと、そのカードが開いて倍率が見える。
  - 札に置いた艦：その札の段階で効くものだけを「■ E2 第三ボス ×1.24」の形で並べる（■ はその段階の札の色）。なければ「この札では特効なし」。
  - 控えの艦：効く札のスコアの高い順に、効く段階をすべて並べる。なければ「特効なし」。
- 開いたカードは、別の艦を選んでも閉じない。もう一度同じ艦を押すと、選択を外して閉じる。
- サブ艦の表記は出さない。

#### 札の列
- 定義の札ごとに 1 列。見出しは札の色で、札名、使う段階、隻数を表示する。
- 艦を選ぶと、その艦がいない札の列に「ここに置く（特効あり）」または「ここに置く（特効なし）」ボタンを出す。押すとその札へ移し、選択を外す。選んだ艦に特効がない札の列は薄く表示する。

#### 選択中の艦のパネル（右側）
- 艦名、「艦種 ・ Lv ・ いま：（札名または控え）」、選択をやめる「×」。
- 「この艦の特効（効く札の順）」：特効がある札ごとにブロックを作り、スコアの高い順に並べる。
  - ブロック：札の色、札名、スコア（例「+81」）、効く段階ごとの倍率（例「E2 第三ボス ×1.27」）、艦種補正があれば別に小さく「艦種 ×1.11」。
  - 「（札名）に置く」ボタン。いまその札にいる場合はボタンの代わりに「いまこの札にいます」。
- 特効がない札は最後に「特効なし：札A、札B」と 1 行にまとめる。
- 艦種補正と艦名グループの倍率を掛け合わせて表示するかは【未決 U5】。

#### ドラッグ＆ドロップ
- 艦のカード（控え・札の列のどちらからでも）をドラッグする。
  - 札の列の空いている所に落とす：その札へ移動する（落とす先の列を強調し、「ここに移動」と表示する）。
  - 別の艦のカードに重ねて落とす：2 隻の札を入れ替える（「⇄ 入れ替え」と表示する）。相手が控えの艦なら、ドラッグした艦が控えに戻り、相手がその札に入る。
  - 控えに落とす：割り当てを外して控えに戻す（札に置いた艦をドラッグしているときだけ控えを強調する）。
  - 自分自身に落とした場合は何もしない。
- ドラッグを始めると、艦の選択は外れる。

#### 保存
- 割り当てはブラウザ内に保存する（5. データの流れ）。

### 3.4 取り込み（艦娘の取り込み。モック：`Import.dc.html`）

- 取り込む形式：**制空権シミュレータの取り込みと同じ形式**。正確なキー名などは、制空権シミュ本体（noro6 氏の公開リポジトリ）のインポート処理を正として確認する【未決 U8】。
- 左側
  1. 「艦娘の情報をコピーする」：「制空権シミュレータに艦娘を反映するときと同じ方法でコピーしてください。」と表示する。どのツールからコピーするかの説明や、ツール別の手順は出さない。
  2. 「ここに貼り付ける」：テキスト欄（「Ctrl+V で貼り付け」）。下に「データはこのブラウザの中だけで読み取ります」、貼り付け後は「貼り付けました（n 文字）」と表示する。
- 右側「取り込む範囲」
  - 「すべての艦娘（未ロックの艦も含める）」または「ロック済みだけ（育成中・保護中の艦に絞る）」。
  - 「Lv がいくつ以上の艦を取り込むか」：「−」「＋」付きの数値欄（1〜185）、「以上」。すぐ選べるボタン Lv1／Lv50／Lv99／Lv150。
  - 「取り込む」ボタン。
- 何も貼り付けずに「取り込む」を押した場合：「まだ何も貼り付けられていません。コピーした艦娘の情報を左の欄に貼り付けてから「取り込む」を押してください」。
- 取り込みに成功した場合：「取り込みました」と次の内容を表示する。
  - 艦娘の隻数（取り込んだ範囲・Lv 下限の条件も添える）。
  - すでに札が付いている艦の隻数（計画との差分に使う）。
  - 名前が分からない艦の隻数（新しく実装された艦かもしれない。取り込みは続けられる）。
  - 「割り振りへ進む」「差分を見る」ボタン。
- 貼り付けたデータはブラウザ内だけで解析し、サーバーに送らない。艦 ID から艦名・艦種・艦型を引くために艦船マスタが必要（入手元は 13.1 の U1）。
- 受け付ける形式（U8。制空権シミュのインポート処理を読んで確認した仕様）
  - `svdata=` で始まる文字列：接頭辞を除いて JSON として読み、`api_data.api_ship` の配列を使う。主な項目は `api_id`（個体 ID）、`api_ship_id`（艦の ID）、`api_lv`、`api_exp[0]`、`api_kyouka[0..6]`（近代化改修：火力・雷装・対空・装甲・運・耐久・対潜）、`api_sally_area`（出撃札）、`api_locked`（ロック）。
  - 短縮形式の JSON 配列：`id`（`ship_id` がある新しい形式では個体 ID）、`ship_id`（艦の ID）、`lv`、`exp[0]`、`st[0..6]`（近代化改修。並びは `api_kyouka` と同じ）、`area`（出撃札）。`ship_id` がない古い形式では `id` が艦の ID で、個体 ID はない。
  - ロックの情報は `svdata=` 形式にしかない。短縮形式では「ロック済みだけ」で絞り込めないため、その旨を表示する【提案】。
  - 艦の ID が 0 または欠けている要素は飛ばす。Lv 下限より低い艦は除く。壊れた入力でも止まらず、理由を表示する。
  - 運の表示値は「艦船マスタの運の初期値 ＋ 近代化改修の運（`st[4]`／`api_kyouka[4]`）」。
- 再取り込みのとき（U9）：個体 ID で同じ個体と判定し、割り当てを引き継ぐ。個体 ID がない古い形式では引き継がず、その旨を表示する。
- モックにない項目：注意書きの枠、お知らせ、「反映手順を表示」、装備の取り込み条件は不要（12 章）。

### 3.5 差分（計画と実際の札。モック：`Drift.dc.html`）

イベント中に、取り込んだ艦娘データの札の情報（`api_sally_area` 相当）と計画を比べる。処理はブラウザ内で完結する。

- ヘッダー：「計画と実際の札」、最新イベント名、「（取り込んだ日時）に取り込んだ札の状態と、計画を比べています」、「最新の状態を取り込む」（取り込み画面へ移動）。
- 件数のまとめ（4 つ）
  - 計画と違う札が付いた（赤）
  - 計画にない艦に札が付いた（橙）
  - 計画どおり（緑）
  - まだ出撃していない（灰。計画では札に置いたが、まだ札が付いていない艦）
- 「対応が必要 n 件」の一覧：1 件ずつ、艦名、「計画の札（取り消し線）→ 実際の札」、説明文、操作ボタンを表示する。
  - 計画と違う札が付いた場合の例：説明「多号作戦部隊で出撃したため、連合艦隊の特効駆逐が1隻減りました（E2-3 ×1.24）。控えの浜波改なら同じ倍率で埋められます。」、ボタン「浜波改を連合艦隊へ」「計画を実際に合わせる」。代わりがいない場合は「代わりの艦を探す」「計画を実際に合わせる」。
  - 計画にない艦に札が付いた場合：ボタン「計画に追加する」。
  - 【未決 U23】代わりの艦の提案（「浜波改を連合艦隊へ」）は、割り振り画面で取り下げた「おすすめ」に近い。差分画面に残すか確認する。
  - 【提案】「代わりの艦を探す」は、空いた札とその段階の特効で絞り込んだ割り振り画面を開く。
- 「計画をまとめて実際に合わせる」（対応が必要なものが 2 件以上あるときに表示）
  - 押すと確認の枠を開く：「次の変更を計画に反映します。合わせないものはチェックを外してください」、1 件ずつのチェックボックス（初期は全部 ON、艦名と「計画 A → B」）。
  - 注意書き：「実際に付いた札が正しいものとして計画を書き換えます。札が抜けた枠は空いたままになるので、あとで割り振り画面で埋めてください」。
  - 「n 件を計画に反映する」（0 件のときは押せない）、「やめる」。
  - 反映後：「n 件を計画に反映しました（艦名・艦名）」と「元に戻す」ボタンを表示する。
- 対応が必要なものがなければ「対応が必要なものはありません」。
- 札ごとの進み具合：札ごとにバーを表示し、「札付き n ／ 計画 m 隻」。
- 【未決 U10】ゲーム内の札の値（`api_sally_area`）と、定義の札を対応付ける方法。

### 3.6 設定（全員・どの画面からでも開くウィンドウ。モック：`Settings.dc.html`、中身：`SettingsDialog.dc.html`）

- 左メニューの「設定」、またはホームの「設定」タイルで、今の画面の上にウィンドウとして開く。後ろの画面は触れない。
- 見出し：「設定」「表示などの設定はこのブラウザに保存されます」、「×」、下に「閉じる」。
- 表示
  - 画面モード：ダーク／ライト／端末に合わせる（明るい場所ではライトが見やすい）。
  - 文字の大きさ：小／標準／大（一覧・割り振り画面の文字の大きさ）。
  - 控えの表示：一行／カード（割り振り画面の控えを開いたときの表示）。
  - 控えの並び順：艦型／Lv／特効の強さ／名前（割り振り画面を開いたときの並び順）。
  - 艦娘のバナー画像を表示（オン／オフ。オフにすると艦名だけの表示になり、通信量が減る）。画像の出所は決まっていない【未決 U13】。
- データ
  - 札割りの書き出し・読み込み（別のブラウザや PC へ移すときに使う）。「書き出す」「読み込む」。ファイルの形式は【未決 U21】。
  - 取り込んだ艦娘データを削除（「最終取り込み（日時） ／ n 隻。札割りは残ります」）。「削除する」。
    - 【提案】削除の前に確認を挟む（取り消せない操作のため）。
- アカウント（協力者・管理者のみ表示）：「ログイン中：（名前）」「権限：管理者／協力者」、「ログアウト」。一般利用者には、この欄もログインボタンも出さない。
  - 【未決 U14】そのため、管理者・協力者がどこからログインするかが決まっていない。

### 3.7 イベント定義（管理者・協力者専用。モック：`PlanEditor.dc.html`）

イベントごとに、札、攻略の段階、特効を設定する画面。公開すると一般の画面に反映される。

#### 上部の欄
- 見出し：「イベント定義」「管理者・協力者専用」「札・攻略の段階・特効を設定します。公開すると全員の割り振り画面に反映されます」、「ログイン中：（名前）（権限）」。
- **管理者**：「既存を更新」「新規作成」を切り替えられる。
- **既存を更新**（更新できるのは最新のイベントだけ。過去のイベントを選ぶ欄はない）
  - 「更新するイベント：（イベント名）（最新）」と「札割りできるのは最新のイベントだけなので、更新も最新のイベントだけです」。
  - 協力者には切り替えを出さず、「更新するイベント：（イベント名）（最新）」「協力者は最新イベントの更新だけができます。新規作成は管理者が行います」と表示する。
  - 開始日時：管理者は変更できる（必須）。協力者は表示だけ。
  - 終了日時（任意）：管理者・協力者とも変更できる。「終了日時を消す」ボタン。「終了日時を過ぎると「開催中」でなくなります。延長されたときはここで直せます」。
  - 入力の検証（その場でエラーを表示）
    - 終了日時が開始日時以前：「終了日時は開始日時より後にしてください」。
    - 終了日時が今より前：「終了日時は今より後にしてください（過去の日時にすると、その場で更新できなくなるため）」。誤ってロックしないため。
  - イベント名：管理者は見出しの欄で直接変更できる。協力者は表示だけ。
  - 状態の表示：「期間：開始 〜 終了（または「終了日時は未定」）」、「公開中：2026/08/04 版 ／ 未公開の変更 n 件（主な変更 ほか）」。
- **新規作成**（管理者のみ）
  - 元にするイベント：「使わない（空から作る）」または過去のイベントを選ぶ。元にすると札と段階をコピーして始める（特効は空）。使わない場合は E1 だけの空の状態から始める。
  - イベント名（必須。例「2026秋イベ」）、開始日時（必須）、終了日時（任意。未定なら空欄で、あとから入れられる）。日時は分まで。
  - 公開ボタンは「公開して最新にする」。イベント名・開始日時が空のまま押すと「イベント名と開始日時を入力してください」、終了日時が開始日時以前なら「終了日時は開始日時より後にしてください」。
- 共有の下書き：「共有の下書き：（日時）に（名前）が保存（保存すると管理者・協力者全員の定義画面に反映されます。一般の画面には公開するまで出ません）」。その横に「保存の記録を見る」（既存の更新時のみ）。
- 編集中の人：「（名前）も編集中（E3 を表示中）」（既存の更新時）。
- 「編集できる人：（管理者・協力者の名前）」。管理者には「協力者を管理」のリンク（協力者画面へ）。
- ボタン：「下書きを保存」、「変更を公開する」（新規作成時は「公開して最新にする」）。

#### 終了したイベント（閲覧のみ）
- 最新イベントの**保存済みの**終了日時を過ぎたら、更新できない状態にする。
- 「このイベントは終了しました（日時 終了）」「終了したイベントは更新できません。内容は見るだけです。」を表示する。下書きの保存と公開のボタンを出さず、本文を操作できない状態（薄く表示）にする。
- 管理者には「次のイベントは「新規作成」から作ってください。」と「新しいイベントを作成」ボタン（新規作成に切り替える）。協力者には「次のイベントは管理者が作成するまでお待ちください。」。
- 【未決 U18】終了後に期間の延長が分かった場合の戻し方は決まっていない。

#### 攻略の流れ
- 見出しの横に操作の説明（「押す：右下で編集・削除」「札を段階へドラッグ：その前に割り込み」「＋：最後に追加」「段階をドラッグ：並べ替え」）。見出しは折り返さない。
- 海域（E1、E2…）ごとに 1 行。段階を左から順に、札の色で並べる。各段階に段階名と札名を表示する。
- 段階を押す：選んだ段階を下の詳細欄で編集する。
- 札（左下の札の一覧から）を段階の上にドラッグする：その段階の**前に新しい段階として割り込む**（上書きしない）。新しい段階の名前は「新しい段階」、大事さは「普通」。
- 札を行の右端の「＋」や空の海域に落とす：その海域の最後に追加する。
- 「＋」を押す：「（海域）の最後に追加する札」のメニューを開き、今ある札から選ぶと、その海域の一番右に段階として追加する。「やめる」で閉じる。
- 段階をドラッグ：並べ替える（別の海域へ移すこともできる）。
- 「＋ E4 を追加」：次の番号の海域（E4、E5…）を追加し、その海域の「＋」メニューを開く。
- 段階がない海域：「まだ段階がありません。右の＋で札を選ぶか、札をここに落としてください」。最後の海域で、海域が 2 つ以上あるときだけ「この海域を外す」を表示する。

#### 札の一覧（左下）
- 定義の札を並べる。各札に、ドラッグの持ち手、札の色、札名、使っている段階の数（「n 段階」）。
- ドラッグで並べ替え・間に割り込み（落とす位置に線を表示する）。
- 「＋ 札を追加」。追加時の入力内容（名前、色など）や、札の名前変更・削除の操作はモックにない【未決 U16】。

#### 段階の詳細（右下）
- 見出し：海域と段階名、札名（札の色で表示）。「この段階を削除」（イベント全体で段階が 1 つしかないときは押せない）。
- 削除の確認：「「E2 ゲージ3」を削除しますか？ 設定した札・大事さ・特効もまとめて消えます。「変更を公開する」を押すまでは一般の画面には反映されません」、「削除する」「やめる」。
- 段階の名前（例「ゲージ2 輸送」）。「新しい段階」なども含めて変更できる。
- この段階で使う札：札の一覧から 1 つ選ぶ。
- 大事さ：普通／重要／難所（重み 1／2／3。特効のスコア計算に使う）。
- 「この段階のボスで効く特効」（「艦名は改装段階を問わず一致します」）
  - 特効グループごとに、倍率（例「×1.27」）、グループ名（例「連合艦隊C」）、艦名のタグ、「＋ 艦名」。
  - 「＋ 特効グループを追加」、「攻略サイトの艦名リストを貼り付け」。
  - 未入力なら「この段階の特効は未入力です」。
  - 倍率・グループ名の変更、艦名やグループの削除の操作はモックで描かれていない【未決 U16】。
  - 艦種補正の入力欄はモックにない（割り振り画面では表示している）【未決 U11】。
- 段階がまったくないとき：「まだ段階がありません。上の攻略の流れで＋を押して札を選ぶと、ここで中身を編集できます」。

#### 同時編集（B 案で決定）
- 共有の下書きは管理者・協力者全員で 1 つ。保存すると全員の定義画面に反映される。一般の画面には公開するまで出ない。
- 保存時の衝突確認：開いた後に他の人が下書きを保存していた場合、次の確認を表示する。
  - 「開いた後に（名前）が下書きを保存していました（日時）」。
  - 違う箇所の変更は自動で合わせる：「自動で合わせた所：E3 ゲージ4 の特効（（名前）が追加）」と「場所を見る」。
  - 同じ項目を 2 人が変えた場合は選ばせる：「同じ所を2人が変えています：E2 ゲージ3 の大事さ どちらを残しますか？」、「（名前）の内容：重要」「あなたの内容：難所」、「場所を見る」。
  - 攻略の流れで、2 人とも変えた段階は**赤く光らせ**「要選択」の印、相手だけが変えた段階は**橙の枠**と「（名前）が変更」の印を付ける。詳細欄でも、衝突した項目を赤く光らせ「（名前）は「重要」に変更しています」と表示する。
  - 「この内容で保存」（選び終わるまで押せない）、「保存をやめる」。
  - 保存後：「下書きを保存しました。（名前）の変更も含めた内容が、管理者・協力者全員の定義画面に反映されます」。自動で合わせた段階の橙の枠は残す。
- 技術的な方式（技術選定時の説明）：下書きに版（version 列）を持ち、保存は RPC（Postgres 関数）で「開いたときの版と同じなら更新」する。差分は段階・特効の単位で取り、画面側で合わせてから保存する。「〇〇も編集中」は Supabase Realtime の Presence で表示する。
  - 【提案】合わせ方は「開いたときの版・自分の内容・相手の保存内容」の 3 つを比べる方式（3 方向マージ）にする。

#### 保存の記録（ウィンドウ）
- 「保存の記録を見る」で、共有の下書きの記録を別ウィンドウで開く（見出し「共有の下書きの記録」とイベント名）。
- 絞り込み：誰が（全員／各人）、種類（すべて／下書き保存／公開）、海域（すべて／E1…）。右に「表示件数 / 該当件数 件」。
- 1 行：日時、誰、種類（「下書き保存」「公開」のバッジ）、内容（例「E2 ゲージ3 の大事さを「難所」→「重要」」「2026/08/04 版を公開」）。
- 8 件ずつ表示し、「さらに古い記録を表示」で追加する。一覧部分だけをスクロールし、絞り込みの欄は上に固定する。該当がなければ「条件に合う記録はありません」。
- 【提案】記録の内容の文は、保存時の差分から自動で作る。

### 3.8 協力者（管理者専用。モック：`Collaborators.dc.html`）

- 見出し：「協力者」「管理者専用」「イベント定義を編集できる人を管理します」。
- 管理者以外が開いた場合：「このページは管理者のみ使えます」「協力者の追加や削除は管理者にお願いしてください」「一覧に戻る」。
- 協力者を招待
  - 説明：招待リンクを発行して送る。リンクを開いてログインすると協力者になり、イベント定義を編集できる。リンクは 1 回だけ使える。協力者の権限に期限はなく、外すまで続く。
  - リンクの有効期限：24 時間／3 日／7 日（無期限は選べない）。「招待リンクを発行」。
  - 発行後：リンク（`https://（サイトのURL）/invite/（招待コード）`）、「コピー」、「（期限）まで有効」。
- 編集できる人（表）：名前、権限（管理者／協力者）、追加した日、権限の期限（「無期限」）、最後に定義を編集（例「08/04（特効を更新）」）、「外す」（管理者の行には出さない）。
- 外すときの確認（すぐには外さない）
  - 「（名前）を協力者から外しますか？」「外すとすぐにイベント定義を編集できなくなります。これまでの編集内容は残ります。もう一度協力してもらうには、新しく招待リンクを発行してください。」
  - 「（名前）を外すことを確認しました」のチェックを入れるまで「外す」を押せない。「やめる」。
- 招待中：まだ使われていないリンクの一覧（「発行日時 ・ 期限 まで有効 ・ まだ使われていません」）と「取り消す」。
- 招待を受ける側の画面はモックにない。【提案】招待リンクを開くと説明とログインボタンを表示し、ログイン後に結果（協力者になった／期限切れ／使用済み／取り消し済み）を表示する。

### 3.9 画像で保存（ウィンドウ：`Main.dc.html` 内、出力画像：`ExportImage.dc.html`）

用途：X などに貼って人に見せる。

#### ウィンドウ
- 見出し：「画像で保存」「横長 1600×900 の PNG。X などに貼りやすい大きさです」。
- 入れる札：「札が付いた札をすべて」または「札を選ぶ」（艦がいる札のチェックボックス）。
- 説明：「入るもの：イベント名・攻略の流れ・札ごとの艦（艦名・Lv・運・特効あり／なし）・ツール名。まだ艦がいない札は入りません。1枚に入るのは6札までで、超えると自動で分けて保存します」。
- 枚数の表示：「n 札 → m 枚（分けて保存）」。札を 1 つも選んでいなければ「札を1つ以上選んでください」。
- 見本（1 枚目）を縮小して表示する。
- 下部のボタン
  - 「やめる」。
  - 「画像をコピー」：ダウンロードせずクリップボードへコピーする。コピー後は「コピーしました ✓」と「画像をコピーしました。Xの投稿欄などにそのまま貼り付けられます」（複数枚なら「n 枚目の画像を…」）。複数枚のときは「コピーする画像」で何枚目かを選ぶ。Clipboard API に対応していないブラウザではボタンを出さない。
  - 「PNGで保存」（複数枚なら「m 枚まとめて保存（PNG）」）。
  - 札を 1 つも選んでいないときは、コピーと保存のボタンを押せない。
- 一覧画面の「制空権シミュへコピー」ボタンは削除済み（一旦なし）。

#### 出力される画像（1600×900）
- 上部：イベント名（大きく）、「札割り」、複数枚のときは右に「n / m」。
- 攻略の流れ：全海域を固定で入れる（段階ごとに札名と段階名を札の色で表示）。
- 札ごとの列：1 枚に最大 6 札（列の幅は最低 3 列分）。列の上端に札の色、札名、隻数。艦は Lv の高い順に、艦名、Lv、運、「特効」（その札で特効あり）または「－」。
- 下部：「札」のロゴ、ツール名、凡例（「特効 その札で特効あり」「－ 特効なし」）。
- 艦に載せる情報は Lv・運・特効あり／なしだけ。イベント名・ツール名・攻略の流れは固定で出す。
- X で縮小されても読めるよう、文字を大きくした見た目にしている（モックが正）。
- 日本語フォント（Noto Sans JP の必要な文字）を読み込んでから描画する。
- 【未決 U15】1 札の艦が多く、画像の高さに収まらない場合の扱い。

## 4. ドメインの用語と概念モデル

### 4.1 用語

| 用語 | 意味 |
|---|---|
| イベント | 艦これの期間限定海域。名前、開始日時（必須・分まで）、終了日時（任意・分まで）を持つ。札割りできるのは最新のイベントだけ。 |
| 最新イベント | 札割り・定義の更新の対象になるイベント。新規作成したイベントは「公開して最新にする」で最新になる。【未決 U18】新規作成して未公開の間の扱い。 |
| 開催中 | 開始日時を過ぎ、終了日時を過ぎていない（終了日時が未定なら終わっていない）状態。【提案】開始日時前の扱いは U18 で決める。 |
| 終了 | 最新イベントの保存済みの終了日時を過ぎた状態。定義は閲覧のみになる。 |
| 海域 | E1、E2…。イベントの中に順番に並ぶ。E4 以降も追加できる。 |
| 攻略段階（段階） | 海域の中の攻略の一区切り（例「ギミック」「ゲージ1 輸送」「ゲージ3」）。順番、名前、使う札 1 つ、大事さ、特効を持つ。札は海域ではなく段階ごとに付く。 |
| 札 | 出撃札。名前、色、並び順を持つ。1 つの札が複数の海域・段階で使われる（例：第三十一戦隊は E1 全体、E2・E3 のギミック、E3-2 輸送）。 |
| 大事さ | 段階の重要度。普通（重み 1）／重要（重み 2）／難所（重み 3）。「難所」は一覧などで印を付ける。 |
| 特効 | 段階 × 対象 × 倍率。段階ごとに「この段階のボスで効く特効」として持つ。倍率はイベントごとに定義画面で設定する。 |
| 特効の対象 | 艦名グループ（名前付きの艦名の集合。例「連合艦隊B」。艦名は改装段階を問わず一致）。艦種ごとの補正（例「駆逐 ×1.11」）は割り振り画面で別に表示する。国籍・装備の補正は MVP では扱わない方向（艦名グループだけでも取り合いの判断に使えるため）。【未決 U11】 |
| 特効データの版 | 公開した定義の日付（例「2026/08/04 版」）。倍率は途中で更新されることがあるため、版を表示する。 |
| 艦の個体 | 取り込んだ艦 1 隻。艦 ID、Lv、運、現在付いている札（`api_sally_area` 相当）などを持つ。**同名艦は別の個体**として扱い、それぞれ別の札に回せる。 |
| 艦船マスタ | 艦 ID から艦名・艦種・艦型などを引くためのデータ。【未決 U1】 |
| 割り当て | 個体を札に置くこと。1 個体につき 0 または 1 つの札。どの札にも置いていない個体が「控え」。 |
| 計画 | 最新イベントでの割り当ての全体。 |
| 実際の札 | 取り込んだデータで、個体に実際に付いている札。差分画面で計画と比べる。 |
| スコア（特効の強さ） | 個体をある札に置いたときの評価。その札を使う段階について Σ（倍率 − 1）× 100 × 重み。例：初霜改二を連合艦隊（E2 ゲージ2：重要、E2 ゲージ3：難所）に置くと、E2 ゲージ3 の ×1.27 だけが効き、(1.27 − 1) × 100 × 3 = 81 →「+81」。 |
| 公開版 | 公開した時点の定義を JSON にしたもの。一般利用者は最新イベントの最新の公開版だけを読む（ログイン不要）。 |
| 共有の下書き | イベントごとに 1 つの、管理者・協力者で共有する編集中の定義。版（version）を持つ。 |
| 保存の記録 | 共有の下書きの保存と公開の記録（日時、誰、種類、海域、内容）。 |
| 招待 | 協力者を追加するためのリンク。1 回限り、有効期限 24 時間／3 日／7 日。取り消せる。使うとログインした人に協力者の権限を付ける。 |

### 4.2 概念の関係

```
イベント 1 ─ * 海域 1 ─ * 攻略段階 * ─ 1 札（札はイベントに属する）
攻略段階 1 ─ * 特効（対象：艦名グループ／艦種 × 倍率）
イベント 1 ─ 1 共有の下書き（版つき） ─ * 保存の記録
イベント 1 ─ * 公開版（JSON。一般向けには最新イベントの最新版だけを配信）
艦船マスタ（艦 ID → 艦名・艦種・艦型…） 1 ─ * 艦の個体（取り込みデータ）
艦の個体 * ─ 0..1 札（割り当て＝計画）
艦の個体 * ─ 0..1 実際の札（取り込みデータの札の値）
管理者 1 ─ * 招待 ─ 0..1 協力者
```

テーブルの詳細設計はまだしない（roadmap の T3-2）。技術選定時に挙がったテーブルの例は、イベント／札／段階／特効グループ／下書き／公開版／保存の記録（このほかに招待と権限が必要）。

### 4.3 公開定義 JSON に入れるもの【提案】

一般の画面と管理者側の契約になるため、早い段階（roadmap の T1-2）で型として固める。

- イベント：ID、名前、開始日時、終了日時、版の日付
- 海域：ID、表示名（E1…）、並び順
- 札：ID、名前、色、並び順、（ゲーム内の札の値【未決 U10】）
- 段階：ID、海域、並び順、名前、札、大事さ
- 特効：段階、対象（艦名グループ名と艦名の一覧／艦種）、倍率

## 5. データの流れ

- **一般利用者**
  - 公開版のうち「最新イベントの公開定義」1 つだけを、静的 JSON として Cloudflare Pages から配信する。過去のイベントの定義は DB にだけ残る。
  - 取り込んだ艦娘データ、割り当て（計画）、設定は、ブラウザ内（IndexedDB。Dexie.js を使う）に保存する。サーバーには送らない。Supabase も使わない。
  - 特効の計算、絞り込み、差分の計算、画像の作成はすべてブラウザ内で行う。
- **管理者・協力者**
  - Supabase Auth でログインし、イベント定義、共有の下書き、保存の記録、招待、権限を Supabase（Postgres）で読み書きする。権限は RLS で強制する。
  - 編集中の表示は Supabase Realtime の Presence を使う。
  - 公開すると、その時点の定義を JSON にして公開版テーブルへ保存する。
  - ビルド時に Supabase から最新イベントの公開版を読み、静的 JSON として出力する（アプリの更新と定義の公開が同じ仕組みに乗る）。公開後に一般利用者へ反映する方式（自動で再ビルドするか）は【未決 U7】。
  - 管理者・協力者が一般の画面を使うときも、一般利用者と同じ静的 JSON とブラウザ内保存を使う（下書きは一般の画面に出ない）。
  - 「一般の画面から Supabase に接続しない」と「一般の画面でも管理メニューを常に表示する」を両立させるため、ログイン中の権限はログイン時・管理画面を開いたときにブラウザへ保存し、一般の画面ではその保存した値でメニューを出す（通信しない）。管理画面を開いたときに Supabase から取り直す。表示の出し分けは補助で、実際の権限は RLS で強制する。
- 【未決 U17】定義の更新（札や段階の削除・変更）や、新しいイベントへの切り替えのときに、ブラウザ内の既存の割り当てをどう扱うか。

| ブラウザ内保存 | Dexie.js（IndexedDB） | 一般利用者の取り込んだ艦娘と札割り |
| ドラッグ＆ドロップ | dnd-kit | 割り振りで艦の移動・入れ替え、定義画面で札や段階の並べ替え |

## 7. 運用と料金

- 想定の利用なら **0 円**。独自ドメインを取る場合だけ年 1,000〜2,000 円程度（取るかは未定。費用が発生するためユーザーが判断する）。
- Vercel は無料枠が非商用に限られるため使わない。
- Supabase 無料プランは、約 7 日間アクセスがないと停止する（停止の約 1 週間前に警告メール。ダッシュボードの Resume で再開）。
  - 停止後に再開できる期間は、資料によって「90 日」と「1 年」で食い違う。作り始める前に最新の条件を確認する【未決 U2】。
  - イベント期間外はアクセスがなくなる可能性が高い。対策として、公開した定義を静的 JSON でも配信し、一般利用者は Supabase を使わない。止まって困るのは管理者・協力者だけなので、イベント前に管理者が Resume を押す運用にする。
- 静的ファイルを節約するため、札割りできるのは最新のイベントだけにする。

## 8. デプロイ（アプリ本体の更新）

- 作業ブランチで push して PR を作る → GitHub Actions で型チェック（tsc）・Lint（ESLint）・単体テスト（Vitest）・画面テスト（Playwright）を実行する。
- Cloudflare Pages の GitHub 連携：PR ごとにプレビュー URL を作り、main へのマージで本番を自動でビルド・デプロイする。本番ブランチは main（D2）なので、main へのマージがそのまま本番 URL への反映になる。
- DB の変更は Supabase CLI のマイグレーション（SQL ファイルで管理）で行い、マージ時に GitHub Actions から本番 DB へ適用する。
- ビルド時に Supabase から最新イベントの公開版を読み、静的 JSON として出力する。
- 失敗したときは、Cloudflare Pages の過去のデプロイへ 1 クリックで戻せる。DB を壊す変更は「足す → 切り替え → 消す」の段階に分けてリリースする。
- Supabase が停止していると、マイグレーションと定義 JSON の取得が失敗する。先に Resume してからマージする。失敗したら再開して再実行する。
- ブラウザ内データの形を変えるときは、古い形からの読み替え（Dexie のバージョン移行）を入れる。
- 参考（正式決定ではない）：定義の「公開」ボタンから自動で反映する案（Supabase Edge Function → Cloudflare Pages の Deploy Hook で再ビルド。1〜2 分で反映）。すぐに反映する必要があれば R2 を使う方式もある。ユーザーの関心はアプリ本体のデプロイの方だった【未決 U7】。

## 9. テスト方針

| 種類 | ツール | タイミング | 主な対象 |
|---|---|---|---|
| 型チェック・Lint | tsc・ESLint | PR ごと（GitHub Actions） | 全体 |
| 単体テスト | Vitest | PR ごと | 特効の計算、取り込みデータの解析、衝突時の差分マージなど |
| 画面テスト | Playwright | PR ごと（CI の中でビルドした静的出力に対して実行する。D1） | 下記の操作 |
| DB のテスト | Supabase CLI（CI 上のローカル Supabase） | PR ごと | RLS・RPC の権限ごとの可否。E2E のログインはテスト用のメール・パスワードのアカウント（本番では無効）で行う（U20） |

Playwright で最初に押さえる操作の候補：

- 取り込み（貼り付け → 隻数の表示）
- 割り振り（ドラッグで移動／入れ替え）
- 画像で保存
- 定義画面（段階の割り込み・削除、衝突確認の表示）
- 権限ごとのメニューと操作の可否

【提案】

- 振る舞いの追加・変更は TDD（テスト → 実装 → レビュー）で進める（roadmap.md の進め方）。
- 計算・解析・マージ・絞り込みなどは画面から切り離した純粋な関数にし、単体テストで細かく確かめる。
- RLS は権限ごとの可否をテストで確かめる（方法は T3-3 で決める）。
- テスト用・プレビュー用の DB をどうするかは【未決 U20】。

## 10. デザイン方針

- 「AI っぽくない」デザインにする。参考にしたサイトと取り入れた要素：
  - 制空権シミュレータ：ダークな下地、上部のツールバー
  - 作戦室（Jervis）：左のツリー型ナビ
  - SEELIE.me：アイコン付きの縦ナビ、行ごとに右端へ状態を置くリスト
  - ペンギン急便：カードより表を中心に情報を詰める作り
- 文字は 12〜13px 程度の日本語フォント（Noto Sans JP など）。角丸は小さめ（2〜4px 中心。ウィンドウなど一部は 6〜8px）。情報は密に並べる。
- 「表を読ませるのではなく、見れば分かる、触れば分かる」。例：艦を選ぶと効く札が分かる。特効の詳細は艦を選んだときにだけ見せる。
- 色はモックの値を基準にする（下地 `#16171B`、面 `#1F2126`、枠 `#2A2D33`、強調の金 `#E8B04B`、操作の青 `#3D6FD0`、管理の橙 `#F0A33A`）。札はそれぞれ固有の色を持つ。ライトモードの色はモックにないため、実装時に決める。
- 他サイトの文言や配置を丸写ししない（取り込み画面で「まるまるコピってる感じなのでアレンジして」との指摘があった）。
- 操作しやすさ：ボタンは押しやすい高さ（モックでは 30〜42px）、ボタンや区切りに適切な役割（role、aria 属性）を付ける。

## 11. 非機能要件

- 性能：控えに 600 隻以上あっても、表示・絞り込み・ドラッグが重くならない。
- プライバシー：取り込んだデータと札割りはブラウザの外に出さない。
- 費用：0 円で運用できる構成にする。
- 可用性：Supabase が停止していても、一般利用者の機能は使える（静的 JSON とブラウザ内保存）。
- 互換性：Clipboard API に対応していないブラウザでは、画像のコピーボタンを出さない。
- 【提案】対象は PC のブラウザを中心にする（モックは PC 幅で作られている）。スマートフォン対応はしていない。

| ボードで割り振りを操作する | ボードは「設定した札割りを見るだけの一覧」。割り振りは専用画面で行う |
| 札ごとの必要隻数の枠 | 不要 |
| おまかせ案（自動の割り振り案）と鍵（艦の固定） | おまかせ案は不要。鍵はおまかせ案とセットだったため外した |
| 決めかねリスト（決めかねている艦） | 不要 |

| 「他札が有利」（例「連合艦隊なら +54」） | 表示しなくてよい |
| 一覧の「札なしの特効艦」の段 | 表示しなくてよい |
| サブ艦の表記・サブ艦タブ・「サブ艦も表示」 | 不要。Lv と運で見分ける |

## 14. 資料の食い違いと判断

- 割り振りモックの特効データには「E1 海域全体」「E1 道中」（重み 0）と「E2 第三ボス」のようなボス名の表示があるが、定義画面のモックは「段階（例：ゲージ3）ごとのボスで効く特効」だけを持つ。この文書は定義画面の形（段階ごとの特効）を正とし、道中・海域全体は U11 とした。【提案】割り振り画面の表示名は「海域＋段階名」（例「E2 ゲージ3」）にする。
